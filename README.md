# Claude Galaxy

Claude Code CLI を複数セッション並列でブラウザから管理する、ローカルホスト専用アプリです。
Windows / macOS / Linux で動作します。

## 必要なもの

- Node.js 18 以上
- `claude` コマンド(Claude Code CLI)が PATH に通っていること
- Windows 10 バージョン 1809 (build 17763) 以降 ※ConPTY を使うため
  - node-pty は Windows (x64 / arm64) 用のビルド済みバイナリ入りなので、通常ビルドツールは不要です
- macOS / Linux: node-pty のビルド環境が必要な場合があります(macOS: Xcode Command Line Tools / Linux: build-essential, python3)

## 起動

### Windows
`start.bat` をダブルクリック(初回は自動で `npm install` を実行し、ブラウザも開きます)。

PowerShell / コマンドプロンプトから起動する場合:
```powershell
npm install
npm start
# → http://localhost:3456
```

ポート変更(PowerShell): `$env:PORT=4000; npm start`
起動コマンド変更(PowerShell): `$env:CLAUDE_CMD="claude --model opus"; npm start`

### macOS / Linux
```bash
npm install
npm start
```
ポート変更: `PORT=4000 npm start` / 起動コマンド変更: `CLAUDE_CMD="claude --model opus" npm start`

## 使い方

- 「＋ 新規セッション」で名前・作業ディレクトリ・起動コマンドを指定して起動
  - 作業ディレクトリ: `C:\Users\you\projects\app` のほか `~\projects\app` も可(エクスプローラーからコピーした引用符付きパスも可)
  - 起動コマンドは `claude` 以外(`powershell`、`cmd` など)も指定可能
  - フルパス指定: `"C:\Users\you\.local\bin\claude.exe"`(スペースを含むパスは引用符で囲む)
  - WSL 内の Claude Code を使う場合: `wsl claude`
- レイアウトは 自動 / 1列 / 2列 / 3列 を切替(設定は保存されます)
- ペイン見出し: ダブルクリックで名前変更、⤢ で最大化、✕ で終了
- `Alt + 1〜9` でペインにフォーカス
- `Shift + Enter` で改行入力(Claude Code の複数行入力)
- `Ctrl + C`: テキスト選択中はコピー、未選択なら通常どおり中断(^C)。`Ctrl + Shift + C` は常にコピー。`Ctrl + V` で貼り付け
- 他のペインに出力があるとステータスの点がオレンジに光ります
- ブラウザをリロードしても、サーバーが動いている限りセッションは維持され、直近の出力(約200KB)が再表示されます
- プロセスが終了したペインには「同じ設定で再起動」ボタンが出ます。Claude Code のセッションなら「▶ 会話を再開」(`claude --resume <ID>`)も出ます

## セッションの保存と再開

サーバーを止めても(`npm start` を閉じる・PC を再起動する)、セッションの一覧は残ります。

- 保存先は `~/.claude-galaxy/sessions.json`(名前・作業ディレクトリ・起動コマンド・Claude のセッション ID・使用量)と `~/.claude-galaxy/logs/<id>.log`(画面出力)です。
- 次に起動すると、前回のセッションが「サーバーの再起動で停止しました」の状態で並び、直近の出力が再表示されます。
- 「▶ 会話を再開」を押すと、同じペインのまま `claude --resume <セッション ID>` で前回の会話の続きから起動します。セッション ID は hooks から受け取るので、Claude Code をこのアプリ経由で起動したセッションだけが対象です。起動コマンドに `--resume` / `--continue` を書いていた場合は、それを外して ID を指定します。
- 「同じ設定で再起動」は、会話を引き継がずに新しく起動します。
- ペインの ✕ で閉じると、保存された記録(一覧とログ)も消えます。Claude Code 側の会話履歴は残るので、`claude --resume` で開くことはできます。
- 自動では再開しません(起動直後にたくさんの Claude が同時に動き出さないように)。

## 権限確認の受信箱

Claude が権限を求めると(コマンドの実行、ファイルの編集など)、サイドバー上部の「承認待ち」と、そのペインの上部にカードが出ます。複数のセッションの確認を 1 か所でさばけます。

| ボタン | 動作 |
| :- | :- |
| 許可 | 今回だけ許可 |
| 今後も許可 | Claude Code が提案した許可ルール(例: `Bash(npm test:*)`)を追加して許可。ルールの保存先(`localSettings` など)はボタンのツールチップに出ます |
| 拒否 | 拒否して Claude に伝えます |
| ターミナルで | 受信箱では答えず、ターミナルの通常の確認ダイアログで答えます |

- サイドバー見出しの「受信箱で承認」をオフにすると、従来どおりターミナルのダイアログだけで答えます(設定は `~/.claude-galaxy/settings.json`)。
- 受信箱で答えないまま 5 分たつと、ターミナルの通常のダイアログに戻ります(`GALAXY_PERMISSION_WAIT=秒数` で変更可)。
- ターミナル側で答えた・中断した場合は、カードは自動で消えます。
- しくみ: `PermissionRequest` hook を同期で登録し、hook がアプリの決定を待って Claude Code に返します。hook が失敗したりアプリが止まっていたりすると、何も返さず通常のダイアログになります。

## 使用量とコスト(概算)

ペインの見出し・サイドバーの各行に概算コストが、サイドバー上部に全セッションの合計が出ます(マウスを乗せると、入力 / 出力 / キャッシュ書込 / キャッシュ読込のトークン数とモデル別の内訳)。

- Claude Code のトランスクリプト(`~/.claude/projects/.../<セッション ID>.jsonl` と、サブエージェントの `subagents/*.jsonl`)を読み、応答ごとの `usage` を合計しています。トランスクリプトの形式は公開仕様ではないため、Claude Code の更新で数えられなくなる可能性があります。
- 単価は API の公開価格(1M トークンあたり)を元にした概算です。サブスクリプション(Pro / Max)で使っている場合の実際の請求額とは一致しません。
- 単価は `~/.claude-galaxy/pricing.json` で上書き・追加できます(モデル ID の先頭一致):
  ```json
  { "claude-opus-5-5": { "input": 4, "output": 20, "cacheWrite": 5, "cacheRead": 0.2 } }
  ```
  `cacheWrite` / `cacheRead` を省くと、input の 1.25 倍 / 0.1 倍で計算します。

## ジョブ(ヘッドレス実行のキュー)

「ジョブ」タブから、Claude Code を画面なし(`claude -p`)で実行するジョブを登録できます。ターミナルを開かずに、決まった作業をまとめて流すためのものです。

- **キュー**: 優先度(高 / 普通 / 低)→ 登録順に、「同時実行」の数まで並行して動かします(既定 2、最大 10)。
- **権限**: `-p` では確認ダイアログを出せないため、確認が要る操作は**受信箱**に出ます。答えなければ(既定 5 分)拒否されます。よく使う操作は「確認なしで許可するツール」(例: `Bash(npm test:*)`)か権限モードで事前に許可できます。
  | 権限モード | 動作 |
  | :- | :- |
  | 既定 | 確認が要る操作は受信箱で答える |
  | plan | 読むだけ・計画だけ(変更しない) |
  | dontAsk | 許可済みの操作だけ実行し、それ以外は確認せずに拒否 |
  | acceptEdits | ファイル編集は確認なし |
  | auto | 安全性の判定に任せる |
  | bypassPermissions | すべて確認なし(注意) |
- **予算**: 「予算 USD」を入れると `--max-budget-usd` で上限を付けます。
- **結果**: 行をクリックすると、経過(テキスト・ツール呼び出し)と結果、コスト、トークン数が見られます。
- **続きをターミナルで**: 終わったジョブの「ターミナルで」を押すと、その会話を `claude --resume` で対話セッションとして開けます。
- 保存先は `~/.claude-galaxy/jobs.json` と `~/.claude-galaxy/jobs/<id>.jsonl`(生の出力)です。終わったジョブは新しいものから 300 件残します。サーバーを止めると実行中のジョブは中断され、待ちのジョブは次の起動で続きから始まります。
- ジョブで使うコマンドは `CLAUDE_CMD` が claude ならそれ、違えば `claude` です(`CLAUDE_JOB_CMD` で変更可)。

### オートメーション

ジョブを自動で登録するきっかけを決められます。

| 種類 | いつ | プロンプトで使える変数 |
| :- | :- | :- |
| ⏱ 時刻 | cron 式(`分 時 日 月 曜日`、ローカル時刻。例: `0 9 * * 1-5` = 平日 9 時) | `{{date}}` `{{time}}` |
| ✎ ファイル変更 | フォルダ内のファイルが変わったら、指定秒数まとめて 1 回 | `{{files}}`(変わったファイル) |
| ⑂ コミット | リポジトリに新しいコミットができたら(15 秒ごとに確認) | `{{commit}}` `{{commitMessage}}` |

- 「前のジョブが実行中なら見送る」をオンにすると、重ねて登録しません(既定オン)。
- ファイル変更では、`node_modules` や `.git` などは数えません。また、自分のジョブが書き換えたファイル(実行中と終了後 5 秒以内)も数えないので、ジョブが自分自身をきっかけに動き続けることはありません。
- サーバーが止まっていた間の時刻の分は、あとから実行しません。
- 保存先は `~/.claude-galaxy/automations.json` です。

## 共有バス(エージェント間のメッセージと共有メモリ)

このアプリで起動する Claude(対話セッションとジョブ)に、MCP サーバー `galaxy`(`mcp-bus.js`)を自動で追加します。複数の Claude が、これを通して協力できます。

| ツール | できること | 確認 |
| :- | :- | :- |
| `list_agents` | 動いているエージェント(セッション・ジョブ)と自分の ID を調べる | なし |
| `send_message` / `read_messages` | ほかのエージェントや**あなた**(`to: "user"`)にメッセージを送る / 自分宛てを読む。`to` には ID・名前・`all`・`parent`(自分を登録したエージェント)を書ける | なし |
| `send_prompt` | 待機中の対話セッションに、プロンプトとして文章を入力して送信する | あり |
| `submit_job` / `get_job` / `list_jobs` / `cancel_job` | ジョブを登録して作業を分担する / 結果を待って受け取る / 自分が登録したジョブを中止する | 登録・中止はあり |
| `memory_write` / `memory_read` / `memory_search` / `memory_delete` | 共有メモリにキーと値で知識を書く・読む・探す・消す | 削除のみあり |

- 「確認あり」のツールは、使うたびに受信箱(またはターミナル)で許可を求めます。それ以外は、このアプリが渡す設定で確認なしにしています。
- エージェントが登録するジョブ: 権限モードは plan / dontAsk / acceptEdits / 既定 だけ使えます。bypassPermissions・auto・許可ツールの指定はできません(人が画面から登録するときだけ使えます)。待ち・実行中のジョブは 20 件まで、ジョブがジョブを登録できるのは 3 段までです。
- エージェントが登録したジョブが終わると、結果は登録したエージェント宛てのメッセージでも届きます。
- 「ボード」タブで、すべてのメッセージと共有メモリを見られます。ここからエージェントに送ったり(待機中の対話セッションなら、そのままプロンプトとして入力することもできます)、共有メモリを書いたり消したりできます。あなた宛てのメッセージがあると、タブに件数が出ます。
- ボードの「共有バスを使う」をオフにすると、MCP サーバーを追加しません(次に起動するものから反映)。
- 保存先は `~/.claude-galaxy/bus.json` です(メッセージは新しいものから 1000 件)。
- MCP の設定ファイルは一時フォルダ(`claude-galaxy/mcp-<ポート>-<ID>.json`)にエージェントごとに作ります。中に本体と通信するためのトークンが入るため、作成者だけが読めるようにし、セッションやジョブが終わると消します。

## 窓口(やりたいことから振り分け)

上部の入力欄(`Ctrl+K` / `⌘K`)に「やりたいこと」を書いて Enter を押すと、どのフォルダで・どの方法で動かすかの**実行案**が出ます。確認・修正してから「実行」を押します(勝手には動きません)。

- 振り分けは、小さいモデル(既定 `haiku`。ツールなし・会話を保存しない)に 1 回だけ問い合わせて決めます。使えないときや答えが読めないときは、依頼文に含まれるフォルダ名などの簡単な規則で決めます。
- 決めるもの: 対話セッションかジョブか / 作業ディレクトリ / worktree を分けるか / 権限モード(ジョブ)/ 名前とプロンプト。
- 候補フォルダは、ホーム画面の「ルート設定」のフォルダとその直下、2 階層下の git リポジトリ、最近使ったフォルダです。
- 対話セッションを選ぶと、起動後に最初のプロンプトを自動で入力します。
- 振り分けに使うモデルは「ツール」タブで変えられます。振り分けのたびに、ごく少額の API 利用料がかかります。

## worktree(作業の分離)

新規セッション・ジョブ・窓口で「別の worktree(ブランチ)で起動する」を選ぶと、git リポジトリの別ブランチ `galaxy/<ID>` の作業コピーを作って、そこで動かします。複数のエージェントが同じリポジトリを同時に触っても衝突しません。

- 置き場所は `~/.claude-galaxy/worktrees/<リポジトリ名>-<ID>` です(「ツール」タブで変更可)。サブフォルダで起動していたら、worktree の中でも同じサブフォルダで動きます。
- ペイン見出しやジョブの行に `⑂ galaxy/s3` のように出ます。
- セッション・ジョブを一覧から消すと、worktree にコミットしていない変更がなければ自動で片付けます(変更が残っていれば残します。`git worktree list` で確認できます)。
- 手動での片付けは差分ダイアログの「worktree を削除」から。コミットしていない変更があると止めます(「変更ごと削除」で強制)。**ブランチは残す**ので、必要な変更は `git merge galaxy/s3` などで取り込めます。不要なら `git branch -D` で消してください。

## 差分と記録(監査ログ)

- **差分**: ペイン見出しの `±`、ジョブの行や詳細の「± 差分」で、そのエージェントの作業場所の `git diff` を見られます。worktree なら作った時点からの変更(コミットを含む)、それ以外は HEAD からの変更です。新しいファイル(未追跡)も中身を表示します(64KB まで)。
- **記録タブ**: エージェントが何をしたかを時系列で見られます。記録するのは、実行したツールとその対象(ファイルパス・コマンドの先頭 300 文字など。ファイルの中身は残しません)、受信箱での許可・拒否、セッション・ジョブの開始と終了、窓口からの実行、worktree の削除です。
  - エージェント・種類・語句・期間で絞り込めます。エージェント名をクリックすると、その人だけに絞り込みます。
  - 保存先は `~/.claude-galaxy/audit/YYYY-MM-DD.jsonl`、既定で 30 日保存します。記録タブでオフにしたり、保存日数を変えたりできます。

## ツール(MCP サーバーの管理)

「ツール」タブで、Claude に渡す MCP サーバーを管理できます。

- **Galaxy の MCP サーバー**: ここに登録したサーバー(stdio / HTTP / SSE)を、新規セッション・ジョブ・窓口のダイアログでチェックして渡せます(`--mcp-config`)。「既定で使う」をオンにしたものは最初から選ばれた状態になります。
  - 「接続確認」で実際に接続し、使えるツールの一覧を表示します(stdio と HTTP)。
  - 環境変数やヘッダーの値は、画面では伏せ字にします。保存先 `~/.claude-galaxy/mcp-servers.json` は本人だけが読める権限で作ります。
  - Claude Code の設定ファイル(`~/.claude.json` など)は書き換えません。
- **Claude Code の設定**: `~/.claude.json`・プロジェクトの `.mcp.json` にある MCP サーバーと、skills / サブエージェント / コマンドの一覧を表示します(読むだけ)。「claude mcp list で確認」で、そのフォルダでの接続状況を確かめられます。

## アプリ(MICRO APPS)

「アプリ」タブに、よく使う Web アプリやコマンドを登録しておけます。登録したアプリは、アプリタブ・ホーム画面左上の MICRO APPS パネル・「新規セッション」のアプリ欄から起動できます。

| 種類 | 登録するもの | 起動すると |
| :- | :- | :- |
| Web アプリ | URL(`https://...`)、またはローカルの HTML ファイル / フォルダ(フォルダなら `index.html`) | アプリタブ内のタブで開く(複数を同時に開いておけます。「↗ 別ウィンドウ」でブラウザの別タブにも開けます) |
| コマンド | 起動コマンド(`codex`、`gemini`、`npm run dev` など)と作業ディレクトリ | ターミナルのセッションとして起動。作業ディレクトリが空なら、起動のたびにダイアログで選びます |

- 一覧は `~/.claude-galaxy/apps.json` に保存されます(初回は Claude Code と PowerShell / Shell が入っています)。
- 外部サイトの中には埋め込み表示を禁止しているものがあります。表示されない場合は「↗ 別ウィンドウ」で開いてください。
- ローカルの HTML は、本体とは別のポート(既定は本体のポート + 1 = `3457`。`APPS_PORT` で変更可)から配信します。オリジンが分かれるので、登録した HTML からこのアプリの API(セッションの起動など)は呼べません。

## サイドバー(エージェントの状態表示)

左のサイドバーに、各セッションの状態とサブエージェントの実行状況が出ます。行をクリックするとそのペインにフォーカスします。`«` で、キャラクターだけの細いレール表示に折りたためます。

| 状態 | キャラの表情と色 | 判定のきっかけ |
| :- | :- | :- |
| 待機中 | 目を閉じて穏やか(オレンジ) | 起動直後 / 入力待ちで放置 |
| 作業中 | 眉を寄せて集中、汗(明るいオレンジ) | プロンプト送信後・ツール実行中 |
| 入力待ち | 目を丸くして「?」(黄) | 権限の確認など、あなたの操作待ち |
| 完了 | にっこり(緑・数秒だけ表示) | 応答が完了 |
| エラー | ×目(赤) | API エラーで中断 |
| 終了 | 眠っている(灰) | プロセス終了 |

- サブエージェントは、種別(Explore / Plan など)・依頼内容・経過時間・完了/実行中を一覧表示します。
- 入力待ちのセッションがあると、ブラウザのタブ名に件数が出て、サイドバーの行が点滅します。別のペインを見ていても気づけます。
- キャラクターは、このアプリ用に作ったオリジナルです。

### 仕組みと注意点

- Claude Code の hooks 機能を使っています。起動コマンドが `claude` のとき、アプリが `--settings <一時ファイル>` を自動で付けて起動し、hook(`hook.js`)がイベントをこのアプリへ通知します。`~/.claude/settings.json` などの設定ファイルは書き換えません。
- hook は `node` コマンドで実行されるため、`node` が PATH にある必要があります。
- 通知するのは、イベント名・ツール名・セッション ID・トランスクリプトの場所・サブエージェントの種別と依頼文・通知メッセージなどに限ります。ファイル内容は送りません。コマンド本文やファイルパスは、権限確認(受信箱の判断材料)のときと、ツール実行後の監査ログ用(対象の先頭 300 文字だけ)に送ります。通知はローカルのこのアプリ(`127.0.0.1`)にだけ送られ、起動ごとのトークンで認証しています。
- `--settings` で渡した hooks が、**あなた自身の hooks と併用されるか**は公式ドキュメントに明記がなく、確認できていません。`~/.claude/settings.json` に自分で hooks を設定している場合は、このアプリ経由で起動したセッションで正しく動くか、一度確認してください。
- 次の場合は hooks を使わず、画面出力の有無から「作業中/待機中」だけを推定します(サブエージェントは表示されません): 起動コマンドが `claude` 以外(`bash` など)/ `wsl claude` / `claude update` などのサブコマンド / `--settings` を自分で指定している場合。

## 仕組み

- `server.js`: Express + ws + node-pty。セッションごとに PTY を持ち、WebSocket で入出力を中継
  - Windows は `cmd.exe /c` 経由(ConPTY)、macOS / Linux はログインシェル経由で起動
- `jobs.js`: ジョブキュー(`claude -p --output-format stream-json` を子プロセスで実行)
- `automations.js` / `cron.js`: オートメーション(cron・ファイル監視・git の HEAD 確認)
- `bus.js` / `mcp-bus.js`: 共有バス(メッセージ・共有メモリ)と、それを Claude に見せる stdio の MCP サーバー
- `audit.js`: 監査ログ / `git.js`: 差分と worktree / `tools.js`: MCP サーバーの管理 / `dispatch.js`: 窓口の振り分け / `cmdline.js`: 起動コマンドの組み立て
- `public/`: xterm.js によるターミナル描画とグリッド UI、ジョブ・ボード画面

## トラブルシューティング

- 「コマンドが見つかりません」: PowerShell で `Get-Command claude` を実行し、表示された場所をフルパスで指定してください。npm でインストールした場合は `%APPDATA%\npm\claude.cmd` です。
- `npm install` が node-pty で失敗する: Node.js が古い、または未対応アーキテクチャの可能性があります。Node.js LTS に更新してください。それでも失敗する場合は Visual Studio Build Tools(「C++ によるデスクトップ開発」)と Python を入れてから再実行してください。
- 日本語が文字化けする: ブラウザ側(xterm)は UTF-8 で表示します。起動コマンドに `cmd` を指定した場合は `chcp 65001` を実行してください。

## セキュリティ

- `127.0.0.1` のみで待ち受け(LAN からは接続不可)
- Host / Origin ヘッダーを検証し、DNS rebinding や他サイトからの WebSocket 乗っ取りを防止
- このアプリはブラウザ経由でシェル相当の操作ができるため、**ポートを外部に公開しないでください**

## 制限事項

- `npm start`(または start.bat のウィンドウ)を閉じると、実行中のプロセスはすべて終了します。一覧と出力は保存され、次回「会話を再開」できます(上の「セッションの保存と再開」)

## ホーム画面(3D フォルダグラフ)

起動すると最初に「ホーム」タブが開き、フォルダ構造が 3D グラフで表示されます(「ターミナル」タブで従来の画面)。

- **ルート設定**: 右パネルの「ルート設定」で、起点にするフォルダを 1 行 1 つで登録(ブラウザに保存)。広すぎるフォルダは深さを浅くしてください。
- **リレーション**: 親子(フォルダ構造)/ 依存(JS・TS の import/require、Python の相対 import をフォルダ間の矢印で表示。太さ=参照数)/ Claude セッション(起動中セッションが cwd のフォルダにぶら下がる。キャラが状態で変化)。
- **フォーカス**: フォルダをクリックするとそのフォルダだけのグラフに切り替わり、配置を放射状に再計算して力学シミュレーションで整えます。Esc / パンくずで戻れます。
- **詳細カード**: ノードを右クリックすると詳細カード(「ここで Claude を起動」など)が開きます。ホバーでは開きません。✕ / 背景クリック / Esc で閉じます(カードが閉じているときの Esc は 1 つ上へ)。
- **ノード操作**: つかんで動かせます(「ドラッグした位置に固定」で固定可)。ホバーで関連ノードを強調、右パネル下のカードから「ここで Claude を起動」。
- **フィルター**: 検索(強調 / 一致のみ)、種別(主な言語)、深さ、最小ファイル数、セッションのあるフォルダのみ、隠しフォルダ、node_modules 等、色分け(言語/深さ/ファイル数)。
- 走査は読み取り専用(ファイルの中身は import 解析のため先頭 128KB のみ読み、外部へは送信しません)。シンボリックリンクはたどりません。

3D ライブラリは `public/vendor/graph3d.bundle.js` に同梱(再ビルド手順: `vendor-src/README.md`)。
